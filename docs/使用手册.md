# nasdash 操作手册（大白话版）

本手册讲清楚 nasdash 这面板**怎么用、每个开关干什么、遇到问题怎么查**。不用懂 Linux 命令，照着点就行。

> 本手册**仅对应当前代码版本 v2.3.3**。以后 nasdash 升级出新版本，本手册会同步更新到对应版本号，老版本用户请回 GitHub Releases 找对应 tag 的手册查看。功能以你实际界面为准，个别主板/风扇命名可能不同，属正常现象。

**本版本修复了什么（v2.3.3 新增）**

| 改动点 | 在哪看 | 说明 / 效果 |
|---|---|---|
| 风扇历史趋势图显示每台风扇各自的曲线 | 历史趋势 · 风扇 | 之前只有一条「平均转速」蓝线；现在每台扇一条彩色曲线，谁转多少一眼看全。 |
| 曲线上标记接管状态 | 历史趋势 · 风扇 | 绿点 = 软件接管、红点 = 交还主板；只在「起始」和「状态变化的拐点」打点，不会密密麻麻。 |
| 历史图直接显示自定义名 | 历史趋势 · 风扇 | 显示你在风扇控制页改的名字；改名后历史库里这台扇所有旧记录也同步改成新名，零残留、历史不丢。 |
| 隐藏的空口扇不在历史图出现 | 历史趋势 · 风扇 | 风扇控制里设成隐藏的扇（如空接的口），历史图也一并隐藏，两边一致。 |
| 风扇改名 / 隐藏稳定保存 | 风扇控制 | 修复 hwmon 重启漂移导致标签错位、改名偶尔「像没保存」；现在稳定留存。 |
| 改名保存按钮交互优化 | 风扇控制 | 编辑名称输入框后自动出现「保存」按钮，点一下立即生效，不用强制刷新页面。 |
| 硬盘温度源预览页修复 | 风扇控制 · 硬盘温度 | 之前偶发把硬盘温度显示为空；现已正确列出每块盘的真实温度。 |

**本版本修复了什么（v2.3.2 新增）**

| 问题 | 在哪看 | 说明 / 效果 |
|---|---|---|
| 风扇控制按硬盘温度源不生效（SAS 盘） | 风扇控制 | SAS 企业盘（阵列卡后）的 `smartctl -A` 输出格式是 `Current Drive Temperature: 34 C`，不是 SATA 盘的 `Temperature_Celsius` 属性表。之前解析漏了 SAS 格式，导致 SAS 盘温度为 `None`，风扇按硬盘温度源计算时等于没有可用温度。v2.3.2 补上 SAS 格式解析，风扇现在能正确按 SAS 盘最热温度调速。 |
| 温度低于开转温度时风扇被主板拉满 | 风扇控制 | 之前温度没到设定的开转温度时，软件会把风扇交还主板自动策略——部分主板此时会把风扇拉到 100% 全速（噪音大）。现在改为按你设的最低转速待机，温度到了再升速。 |
| 组了 RAID 的机器看不到「逻辑盘 / 一致性检查 / 热备盘」 | 硬件配置检测 | 之前解析阵列卡逻辑盘列表时遇分隔线就停，逻辑盘恒为空，组了 RAID5 等阵列的机器上这些区块被误判"无逻辑盘"整块隐藏。现修复，虚拟盘通道标注也改为「阵列卡虚拟盘（RAID5）」。JBOD 直通（未建逻辑盘）时整块隐藏仍是正常设计。 |
| 温度监控页看不到 RAID 成员盘温度 | 温度监控 · 风扇控制 | 组 RAID 后成员盘在系统里没有独立盘符，之前温度页看不到它们。v2.3.2 新增「阵列卡硬盘」温度组，由阵列卡上报温度并展示；SAS 盘在温度卡片上带「SAS」身份角标，和 SATA 盘一眼区分。 |

**本版本修复了什么（v2.3.1 新增）**

nasdash 2.3.1 是一次针对论坛反馈的修复版：

**修复**

| 问题 | 在哪看 | 说明 / 效果 |
|---|---|---|
| 阵列卡温度显示偏差 | 温度监控 · 硬件配置检测 | 之前只显示 ROC 芯片温度（偏高），与飞牛界面 / storcli 对照工具看到的「控制器温度」差好几度、刷新永远对不上。现同时展示两个独立传感器温度（芯片 ROC + 控制器），并标注两者差异原因（不同传感器、非故障）；温度采集缓存由 60s 收紧到 15s，缩短采集失败后的恢复时间。 |
| 阵列卡背后的物理盘看不到 | 硬盘 SMART · 硬件配置检测 | v2.3.0 后端已把组 RAID 后系统无 /dev 节点的物理盘加进列表，但前端用空盘符当唯一身份证，导致多块盘只渲染成一张（看起来=消失）。现给每块盘分配阵列卡唯一身份证并按槽位命名，物理盘全部可见、点开可看通道与健康；无 /dev 节点故不支持自检（已禁用按钮并说明）。检测页盘列表同步补全盘名。 |

nasdash 2.3.0（上一版）是在界面重构（2.2.0）之后的一次功能补强：给 6 个硬件页补齐了实用小功能，并把「一键健康报告」整份重做了一遍，同时修掉几个显示不准的老问题：

**新增**

| 功能 | 在哪看 | 说明 / 效果 |
|---|---|---|
| 网卡唤醒开关 | 硬件配置检测 → 网卡 | 以前只能看到「支不支持网络唤醒」，现在可以直接开关，**设置重启后还在**（远程开机不用再进主板 BIOS 折腾）。 |
| 网卡未跑满提示 | 硬件配置检测 → 网卡 | 换上 2.5G 网卡（如 Intel I226-V）却只跑到千兆 / 百兆时，网卡卡片会提示「此网卡最高支持 2.5G，当前只协商到 N，未跑满」，帮你判断是网线还是对端路由器口拖了后腿；接上 2.5G 网口跑满后提示自动消失。 |
| 硬盘健康分级 + 缺陷增长趋势 | 硬盘 SMART | 每块硬盘带一个**绿 / 黄 / 红**健康徽章，点开看「为什么判成这样」；面板每 6 小时记一次缺陷数，**这块盘是在变好还是继续恶化，一眼看出来**。 |
| 给硬盘改个好记的名字 | 硬盘 SMART | 阵列卡上的槽位名（如 `E0:S3`）看不懂也不好记，可以改成「数据盘1」这类名字，重启不丢。 |
| 存储卷映射树 | 存储卷 | 看清「**哪块物理盘 → 走了哪个阵列 → 变成了哪个存储卷**」，排查问题不用来回翻页对照。 |
| 温度预警红线 | 历史趋势 → 温度 | 自己设一条红线（默认 75℃，可调 30–120℃），曲线一过线就知道，不用盯着数字算。 |
| 内存详细信息弹窗 | 硬件配置检测 → 内存 | **点一下内存卡**，弹出完整参数：颗粒厂商、Rank、位宽、电压、生产日期、序列号、内存错误计数等（直接从内存条的芯片里读）。条子本身没写入的项会如实标「**不适用（原因）**」，不编数字。 |
| 健康报告「脱敏导出」 | 控制与自动化 → 一键健康报告 | 勾一下再导出，**内网 IP、MAC、序列号、云盘账号名全部打码**。要贴论坛、发群里求助时不怕漏隐私。 |
| **端口占用（含应用归属）** | 其他 → 🔌 端口占用 | 新增一页，列出 NAS 上**所有正在被监听的端口**，并自动认出**是哪个应用 / 容器 / 系统服务在占用**（应用显示真名和它自己的图标，系统服务配中文说明）。支持按来源筛选、按端口或应用名搜索（能搜中文）；每个端口可**一键释放**，需二次确认，系统关键进程不会被误杀。 |

**优化与修复**

| 功能 | 在哪看 | 说明 / 效果 |
|---|---|---|
| 健康报告整份重做 | 控制与自动化 → 一键健康报告 | ①「阵列卡」段原来只列了**软阵列**（容易让人误会成阵列卡建的），现在拆成「**阵列卡（硬件）**」与「**系统软阵列**」两段，固件版本、掉电保护、卡温、物理盘列表全补上；② 硬盘段改成「概览 + 每块盘详情」，序列号、接法、转速、累计读写量都有；③ 系统段补上操作系统 / 内核版本 / CPU 功耗；④ 网卡补型号、驱动、双工、MTU、IPv6；⑤ 去掉温度表里几个**「0℃」假读数**（没接传感器的测点）和一堆看不懂的 `in0`~`in14` 电压噪音。 |
| 双磁臂硬盘不再被当成两块盘 | 硬盘 SMART / 健康报告 | 有一类硬盘内部是两个磁臂，系统会把它认成两个设备。之前报表里会多算出一块盘，现在正确合并成一块，**盘数和总容量都对了**。 |
| 后端断开时有提示 | 全局 | 面板连续取不到数据超过 10 秒，顶部会弹出一条黄色提示告诉你「数据多久没更新了」，不用自己猜是不是卡死。 |
| 风扇页状态说明 | 风扇控制 | 顶部一行大白话说明当前是「**面板在接管调速**」还是「**交还主板自动管**」；一切正常时不打扰，有异常才提示。 |
| CPU「更多参数」去重 | 硬件配置检测 → 处理器 | 频率信息重复显示了两遍，去掉一处。 |
| 安装包瘦身 | — | 重构期一直留着的旧版界面兜底通道已退休，**安装包小了约 90KB**。 |
| 【论坛反馈】阵列卡硬盘与温度完整显示 | 硬盘 SMART / 硬件配置检测 | 来自 fnOS 论坛反馈（N10-NAS，MR9362-8i / 7 块盘）：之前用 LSI MegaRAID 这类阵列卡的机器，硬盘列表里要么型号被识别成 `U` / `D` 这类怪字符、要么阵列卡背后的物理盘根本不出现、硬盘温度也读不到。已修好型号解析、补回阵列卡背后的物理盘，现在列表里能看到完整的盘、型号和温度都正常。 |
| 【论坛反馈】风扇温度源加入阵列卡 | 风扇控制 / 温度监控 | 来自同一论坛反馈：之前风扇调速只能跟 CPU / 主板 / 硬盘温度，现在新增「**阵列卡**」温度源，温度监控页与风扇控制页的「当前温度」栏也会显示阵列卡温度，机箱风扇可按 RAID 卡温度自动增减风量。 |

**优化与修复**

| 功能 | 在哪看 | 说明 / 效果 |
|---|---|---|
| 界面引擎整体换新 | 所有页签 | 全部 11 个页面底层换用新界面引擎重做（界面样式与旧版一致）：页签切换零刷新、打开更快、操作不卡顿 |
| 页签秒开 | 所有页签 | 切走再切回的页签**立即显示上一次的内容**（后台自动更新到最新），不再每次都白屏等加载 |
| 运行日志表格化 | 控制与自动化页 → 运行日志 | 日志改为表格（序号 / 时间 / 请求 / 状态 / 大小），状态直接显示「成功 / 请求异常」等通俗说法（悬停可看原始状态码）；去掉无意义的来源 IP 列，时间简化为「月-日 时:分:秒」，请求路径里的防缓存乱码参数也一并清理；反馈问题时直接说「第几行」就行 |

| 风扇转速秒级刷新 | 风扇控制页 | 每风扇实时转速与顶部「平均转速」改为**每秒刷新**（与 CPU 频率同款），调速变化立刻可见 |
| CPU 当前频率更准、更快 | 硬件配置检测 → 处理器 | 频率改为**全部核心的平均值**（原来只看第一个核，数字会随单核负载乱跳）；并且**每秒刷新**，蓝色数字表示实时更新中，附带频率范围参考 |

| 运行日志错误样式修复 | 控制与自动化页 | 旧版运行日志里的错误条目不显示红色错误样式（样式类名对不上），新版错误条目正确高亮 |
| 磁盘 I/O 漏盘修复 | 系统资源 → 磁盘 I/O | NVMe 等设备名以数字结尾的**整盘**不再被漏掉（如 NVMe 系统盘）；RAID / LVM 等虚拟层不重复计数，只统计真实物理盘 |
| 内存条厂商识别扩充 | 硬件配置检测 → 内存 | 厂商对照表新增 11 家（紫光、晋华、长鑫、兆易创新、华邦、钰创、力晶、晶豪、瑞萨等），国产/工控内存条不再显示英文代号 |
| 存储卷小百分比裁切修复 | 存储卷 | 使用率很低时（如 0.5%），进度条里的百分比数字不再被裁切显示不全 |

**往期版本修复（2.0.9）**

nasdash 2.0.9 主要新增了历史趋势页（六维度切换）与一键分析报告导出，并修复了飞牛升级后风扇页刷新卡死 / 接管要等近 1 分钟的故障：

| 功能 | 在哪看 | 说明 / 效果 |
|---|---|---|
| 历史趋势页（新增） | 历史趋势页 | 新增历史趋势查看功能，支持 24 小时 / 7 天 / 30 天时间范围切换，数据来自面板后台持续记录的历史库 |
| 手册历史趋势章节 + 报告导出说明 | 本手册第 4 章 | 历史趋势页是**六维度切换**（磁盘 I/O、网络、功耗、温度、风扇、内存），手册已写成对应表格说明；新增 4.1「生成分析报告」，讲清 HTML / Markdown / CSV 三种报告怎么打开 |

> ⚠️ **关于"条件不满足自动隐藏"——这是设计，不是故障**
> 上面「阵列卡增强」表里前 6 项功能都建立在「阵列卡建了**硬件 RAID 逻辑盘（VD）**」的基础上。你的阵列卡是 **JBOD 直通**模式（硬盘由系统直接管，没有逻辑盘），所以这些功能在你这台机器上是**整块整块地自动隐藏**的——面板该显示什么、不该显示什么，代码里已经按条件判断好了，你看到的就是正确结果，不会报错、也不会点出红错。
> 等你在一台**建了逻辑盘 + 热备盘**的机器上装本面板，这些区块会**自动出现**，无需任何设置。
> 另外「物理盘定位闪灯」还有一个额外门槛：机箱**背板要支持定位信号（SGPIO/SES）**。不支持的话，连这一行的按钮都不会显示（本机被动背板即属此类）。
> 只有「告警分级」是通用告警能力，**任何机器都能用**，没有隐藏条件。

## 一、先搞明白：nasdash 是什么

nasdash 是飞牛OS（fnOS）上的一个**硬件监控面板**，把原本要 SSH 敲命令才能看的硬件状态，做成网页一眼看完：

- 你有什么硬件（CPU/内存/主板/显卡/阵列卡/网卡）
- 硬盘健不健康、多少度
- 风扇转多快、能不能调速
- 阵列卡/Raid 状态、存储卷用了多少
- Docker 容器在不在跑
- 哪些端口被谁占着（应用 / 容器 / 系统服务）
- 温度高了会不会自动报警

一句话：**它是你 NAS 的「仪表盘 + 风扇遥控 + 报警器」三合一**。

---

## 二、怎么打开

1. 在飞牛OS **应用中心**装好 nasdash（手动安装 `nasdash.fpk`）。
2. 桌面会出现「NAS硬件监控」图标，点开即进入。
3. 面板嵌在飞牛桌面里（应用中心打开即进入），**要先登录飞牛账号**才能看。
4. 外部访问请走飞牛自带的远程访问 / 反代，**不要直接把 9800 端口暴露到公网**。

> 小提示：面板每 30 秒左右自动刷新（系统资源页有「自动刷新」开关）。

## 三、各模块逐一讲解

左侧边栏共十个功能模块（硬件配置检测 / 系统资源 / 温度监控 / 历史趋势 / 硬盘 SMART / 存储卷 / 风扇控制 / Docker / 端口占用 / 控制与自动化），外加「操作手册」和「关于 nasdash」两个常驻入口，下面挨个说。

### 1. 硬件配置检测（首页仪表盘）

进面板第一眼就是它，单页总览，按硬件分卡片平铺：

- **顶部状态栏**：阵列卡 / 硬盘 / Docker / 系统负载一屏速览。
- **处理器**：型号、核心/线程数、**实时频率**、**CPU 温度**、当前负载占用。
- **显卡**：独立成卡。核显、独显分别列出，每张显示 **型号、PCIe（地址与通道上下合并显示，含中文明文说明）、驱动（含版本）、显存容量、核心频率、显存频率、显存位宽、GPU 温度、功耗** 等项。驱动行统一显示「模块名 + 版本」：NVIDIA 用 `nvidia-smi` 的官方驱动版本号（如 `nvidia 535.86.05`）；AMD/Intel 开源驱动（amdgpu/i915）随内核发布、无独立版本号，飞牛精简系统也未预装 `modinfo`，故显示其所在**内核版本**（如 `amdgpu 6.18.18`）。独显（NVIDIA）通过 `nvidia-smi` 取实时显存/频率/位宽/温度/功耗；AMD 独显通过 `amdgpu` 驱动的 sysfs 接口（`pp_dpm_sclk/mclk` 当前档，回退 `hwmon` 的 `freq1/freq2_input`）读核心频率与显存频率，温度与功耗（瞬时 `power1_input`、上限 `power1_cap`）取 `amdgpu` hwmon，显存容量取 `lspci` 显存区间；还读 `lspci -vvv` 显示**当前实际跑在 PCIe 几代、几条通道**（如「PCIe 4.0 x16（协商 x16，上限 x16）」）；若被主板降到 x8 会标橙字「未跑满」，一眼看出卡没插满速。**功耗**一行同时显示「瞬时功耗（W） / 上限（W）」，接近上限（≥85%）变橙、≥95% 变红，一眼看出卡是不是撞了功耗墙被限速。**AMD 显存位宽** amdgpu 没有标准接口暴露，用「设备 ID → 位宽查表」解决（如 RX 6600 XT 设备号 0x73ff = Navi 23 = 128 位、RX 6800 系列 0x73bf = 256 位），查表覆盖 RX 5000/6000 常见型号；未收录的型号会灰字提示「暂未识别」。核显读得到核心频率（如 350 MHz），温度取 CPU 同封装温度、显存标「共享系统内存」、PCIe 项标「集成于 CPU，不占用独立 PCIe 插槽」、功耗标「核显与 CPU 共用电源，未单独统计」。**核显本就没有独立显存**，所以「显存频率 / 显存位宽」会直接写明原因（如「核显与 CPU 共用内存，无独立显存频率」），而不是显示一个没意义的 0 或「—」。只插独显时主板 BIOS 常自动禁用核显，这条也会提示出来，不会凭空消失。
- **内存**：按主板插槽画成若干小方块（已插的实色、空槽灰显），并标出是**单通道还是双通道**；品牌取自 SPD 直读，区分「模组厂」和「颗粒厂」（比如模组是某品牌、颗粒是三星），还会标颗粒厂。
- **主板型号**：由主板 DMI 信息自动读取（品牌 / 型号 / 版本 / BIOS / 芯片组）；DMI 读不到时回退显示芯片组推断，并注明「BIOS 未写入主板信息」。
- **系统信息**：已运行多久、**交换分区（swap）用了多少**等。
- **温度墙**：主板所有温度测点集中成一张彩色小卡片墙，绿=正常 / 橙=偏高 / 红=危险；自动过滤掉 0°C、负温这类无效测点，不会再用一堆 0 度填满屏幕。英文代号（如 `AUXTIN0`、`CPUTIN`、`SYSTIN`）已自动翻译成中文，鼠标悬停在小卡片上还能看到原始英文名，方便核对。
- **网络**：只列真实网卡（已自动过滤 ovs、veth、docker 等虚拟接口），显示 IP / 协商速率 / 连接状态，以及实时上下行流量。
- **阵列卡 & 磁盘**：卡型号 + 物理盘，SMART 健康速览。

> 没看懂的字段不用管，这一页就是「看个全貌」，颜色异常再点进去细看。

#### 1.1 阵列卡（在硬件配置检测页内）

面板用 `lspci` 自动识别你插的是哪种卡，分三种情况显示，**不会瞎报**：

- **MegaRAID 阵列卡**（如 LSI 9271-8i，RAID/IR 模式）：显示型号 / 序列号 / SAS 地址 / 固件 / BIOS / 驱动 / PCI 地址、CacheVault 缓存电池状态、**ROC 芯片温度**、JBOD 物理盘列表（槽位 / 品牌 / 型号 / 接口 / 容量 / 状态 / 转速）。
- **HBA 直通卡**（如 LSI 9300，IT 模式）：显示卡型号 + 「IT 直通模式」说明，额外显示 **HBA 芯片温度**。直通卡下的盘由系统直接识别成 `/dev/sdX`，温度去「硬盘 SMART」标签页看。
- **纯 SATA 主板**（没独立阵列卡）：提示「无独立阵列卡」，温度请见「硬盘 SMART」。

> **双磁臂（双执行器）硬盘**：阵列卡会把每个执行器当独立盘暴露给系统（容量会被分别列出），面板会识别并合并成一块盘，显示整盘标称容量并标注每执行器容量——这是正常的，不是 bug。

> **逻辑盘 / 缓存策略 / 一致性检查卡（条件显示）**：硬件配置检测页里的「逻辑盘（Virtual Drive）· 缓存策略」卡（含一致性检查 Consistency Check 操作），**只有在阵列卡上确实存在硬件 RAID 逻辑盘（Virtual Drive）时才会出现**。若你把硬盘设为 **JBOD 直通模式**、由系统层（如 mdadm）管理阵列，阵列卡上没有逻辑盘，这张卡会自动隐藏——这是正常的：并非阵列卡不支持缓存策略，而是没有可显示的硬件逻辑盘。改用阵列卡建立 RAID 卷（VD）后，此卡会自动出现，列出每块逻辑盘的级别 / 容量 / 状态 / 访问权限 / 写回(WB)·直写(WT) 策略，并可在其上发起一致性检查（支持开始 / 暂停 / 恢复 / 停止）。

### 2. 系统资源（任务管理器风格 + 网络监控）

打开就是一块「任务管理器」式的实时面板，左边几张大卡片，**CPU 使用率 / 内存 / 实时功耗 / 网络收发**一目了然：

- **CPU**：大百分比 + 进度条（蓝条随使用率增长），实时更新；旁边附 CPU/内存的 **60 秒滚动折线**（每 1 秒一个点，最近一分钟的起伏一眼看清）。
- **内存 / Swap**：使用率进度条。
- **实时功耗**：CPU+内存的实时功耗（RAPL 硬件测量，Intel CPU 才有；数值超过 40W 标红、超 20W 标橙，绿色=省电状态）。
- **网络实时速率**：合并全部有效网口显示上传 / 下载总速率（每秒刷新）+ 60 秒滚动折线（任务管理器风格）；虚拟网口和重复桥接口会过滤，避免重复统计。各网卡的 IP / MAC / 协商速率等静态详情仍在「硬件配置检测」首页查看。
- **网卡静态详情**（IP / MAC / 协商速率 / 双工 / MTU / 厂商 / 驱动 / PCI 位置 / UP-DOWN）在「硬件配置检测」首页的网络卡片里，不在本页。

> 以前这页还摆过「温度传感器 / 风扇转速 / 电压」——2.0.4 起那些挪到「温度监控」「风扇控制」专属页面了，这里只留 CPU/内存/功耗/网络，页面更聚焦。

### 3. 温度监控（温度墙 + 最高/平均）

看全机温度的地方：

- 顶部 hero 四个数：**CPU 温度 / 阵列卡温度 / 最高温度 / 平均温度**。
- 下面是一整面**温度墙**（彩色小卡片墙）：主板所有温度测点 + 阵列卡芯片温度 + **显卡（核显 / 独显）温度**，绿=正常 / 橙=偏高 / 红=危险；温度数值统一取整显示（没有 38.9 这种小数）。
- 显卡温度会自动识别：核显标「核显」、独显标「独显」，插了多张卡会自动加型号名区分；插了独显且系统装好对应驱动（NVIDIA 的 `nvidia-smi` / AMD 的 amdgpu）就会自动出现，无需设置。核显温度取 CPU 同封装温度，数值接近 CPU 属正常。
- 主板温度现在优先取 ACPI 的 `acpitz`（系统环境温度，最稳）；原来的 `SYSTIN` 不会消失，只是改名成「主板(SYSTIN)」保留显示，方便核对。
- 各硬盘温度 + **核心**（CPU/主板）· **NVMe** · **SSD** · **机械** 分组展示在「风扇控制」页顶部的当前温度概览里，不在这页。
- 「CPU 封装温度」带 **★最准** 角标（CPU 内部传感器直读，最准确）；鼠标**悬停**在卡片上能看到原始测点名（如 CPUTIN/SYSTIN）。
- 每 **5 秒**自动刷新，数字实时变化，不用手动点。

### 5. 硬盘 SMART

所有硬盘的健康体检页：

- 同时支持 **SAS/SCSI 盘** 和 **SATA/ATA 盘**。
- 自动识别品牌与特性（希捷/西数/东芝/三星，双磁臂盘带徽章）。
- 健康状态：OK/PASSED 标绿，异常标红。
- 温度 / 通电时长 / 坏块计数 / 错误计数。
- **机械盘显示真实转速**（7200 rpm / 5400 rpm）；**SSD 显示「固态(SSD)」**。
- SATA 盘额外显示 Reallocated / Pending / Uncorrectable / UDMA CRC 等告警计数。

> 这块盘到底是不是 SSD，面板靠内核 `rotational` 值判断（0=固态 / 1=机械），准的。

#### 5.1 硬盘自检：一个入口，三种扫法

2.0.5 起，「硬盘 SMART」板块每块盘上有一个「硬盘自检」按钮，点开后**按这块盘的情况**给你可选的方式（正在用的盘不会出现清空式扫描，避免误操作）：

**方式一 · SMART 长自检（固件级，只读、不伤数据）**
- 由硬盘固件自己体检盘体逻辑健康，适合二手盘 / 老盘体检。
- 点「SMART 长自检」→ 后台运行，进度条实时显示百分比，跑完给出 PASS / FAIL 结论。
- 想中途停就点「中止」，随时可取消。

**方式二 · 只读表面扫描（仿硬盘哨兵，所有盘都能跑）**
- 像硬盘哨兵那样**只读**逐扇区扫盘面，判断每个扇区能不能正常读出，**不写任何数据、不伤盘**。
- **所有盘都能跑**：正在用的盘、阵列成员、独立盘都可以。
- 扫描时会显示一张 80×8 的扇区网格图：灰=还没扫到、绿=扫过正常、红=坏块、黄=当前扫描位置，进度实时填充。
- 扫描进行中可点「最小化」把面板收成一行小条（盘名+进度），后台继续扫，随时「展开」看回网格。

**方式三 · 全面坏块扫描（写满清空，仅独立盘可选）**
- 彻底排查盘体物理坏道：会把整盘写满再清空，**数据会被清空**，只用来测盘、别在有数据的盘上跑。
- 只有「独立盘」（未挂载、且不在 RAID 阵列 / LVM 里）会出现这个选项；在用盘不会显示，避免误清数据。
- 进度同样实时可见并带扇区网格；0% 阶段会显示「计算中」并给出参考总用时，不会看着像卡住。

> 一句话：SMART 长自检是「固件体检」（不伤数据），只读表面扫描是「哨兵式表面扫描」（不伤数据、任何盘都能跑），全面坏块扫描是「退役前彻查」（清空数据、仅独立盘）。日常监控用前两种就够。

### 7. 风扇控制（重点模块）

这是最能「动手」的模块。三块内容：**预设调速 / 温控曲线（含逐风扇联动）/ 安全接管**。

#### 7.1 预设档位与自定义

- 预设档位（默认 / 全速 / 停转(0%) / 10%…90%）一键调速，卡片实时显示 RPM 与占空比。
- 每个风扇可**网页改名**（如「CPU 风扇」「机箱风扇」）和标供电电压（12V / 5V / 未知），按安装实例持久化。
- **同名风扇自动合并**：如果你给多台风扇设了**相同名称**，面板会判定它们是同一物理风扇（主板把同一个风扇识别成了两张卡），自动**合并成一张卡**，改名/隐藏/调速会**同步到全部同名通道**——专门解决「明明一个风扇、却显示成两张卡、改一个名另一个不动」的问题。想让它们各自独立，只要设成不同名称即可。
- 手动调速下限放宽到 **0%（停转）**；点「恢复自动」即把风扇交还主板/内核自动控温。

#### 7.1b 调速方式：PWM 还是 DC（风扇根本不听话时先看这里）

风扇卡片标题栏有个「**PWM 调速 / DC 调速**」的下拉框，它说的是**主板这个插座用什么方式来控速**：

| 方式 | 对应风扇 | 原理（大白话） |
|------|---------|--------------|
| **PWM** | 4 针风扇 | 多出来的第 4 根线是专门的「调速信号线」，主板按这根线的指令控速，供电电压始终是满的 |
| **DC** | 3 针风扇 | 没有信号线，只能靠**调高调低供电电压**来控速，电压低转得慢 |

**为什么要管这个？** 如果你插的是 3 针风扇，而主板这个口被设成了 PWM，风扇收不到任何调速指令，就会**一直全速狂转**——不管你在面板上怎么调都没用。这是「调速不生效」最常见的原因，比软件 bug 常见得多。这时把该口切成 **DC** 就好了。

**怎么判断自己是哪种？** 看插头上的针数：4 针是 PWM，3 针是 DC。也可以直接试——调到 30% 看风扇转速有没有降，没降八成就是插错了方式。

**⚠️ 能不能切，主板说了算。** 很多主板只有一两个口（一般是 CPU_FAN、PUMP）做了 PWM/DC 双模式电路，剩下的口出厂就焊死只能走 PWM。切不动的口，面板会直接告诉你「该接口硬件只支持 PWM 模式，无法切换（主板限制，非软件问题）」，并把下拉框弹回真实状态——**不会假装切成功**。碰到这种情况只有两条路：进 BIOS 找找有没有对应选项，或者换一把 4 针风扇。

**切到 DC 之后注意：** DC 是靠降电压控速的，电压太低风扇可能**转不动或者干脆停了**（PWM 就不会，它电压始终是满的）。所以 DC 模式下的卡片会多出一行蓝色提示。如果发现风扇低速时抖动、启动不起来，把最低转速调高一点（比如从 20% 提到 35%），或者干脆切回 PWM。

#### 7.1c 转速一直显示 0？勾一下「无反馈线」

有些风扇（尤其是机箱自带的、或者跟阵列卡/硬盘笼一起送的）是 **2 针或 3 针**的，线上**没有转速反馈线**。这种风扇转得好好的，但主板读不到它转多少，面板上就一直显示 `0 转`——看着像坏了，其实完全正常。

风扇卡片标题栏里有个「**无反馈线**」的勾选框，勾上再点「保存标注」，这一栏就不再显示刺眼的 0，改成显示「**— 无反馈线（正常）**」，也不会再被当成故障风扇。

**勾上之后还有个附带好处：** 如果这口同时还是 **PWM 调速**，卡片会弹一条橙色警告——

> ⚠️ **这口的百分比可能不起作用。**没有反馈线的风扇通常也没有 PWM 信号线，收不到调速指令，供电一直给满，很可能**始终全速转**，面板上调多少都没反应。

这条提示能帮你省下大把排查时间：**转速读不到**和**调速调不动**，在 2/3 针风扇上往往是同一个原因——线不够。解决办法就是上面 7.1b 讲的：切 DC、进 BIOS、或者换 4 针风扇。

**注意区分两种「读不到转速」：**

| 情况 | 面板显示 | 该怎么办 |
|------|---------|---------|
| 确实接了 2/3 针风扇 | 勾「无反馈线」后显示「— 无反馈线（正常）」 | 正常，不用管 |
| 这口压根没插风扇 | 不勾，显示「— 无转速信号」 | 点「隐藏」把这个空通道收起来 |

#### 7.2 两套独立温控曲线

面板能按温度自动调风扇，且**两套互不干扰、可分别接管不同风扇**：

**A. 硬盘温控（disk_temp）—— 看盘的温度调风扇**

适用场景：你想让「硬盘散热风扇」跟着硬盘温度走（盘热就多吹，盘凉就少吹）。

配置步骤：
1. 勾 **「启用硬盘温控」**。
2. **监控硬盘**：勾你想盯的盘（界面每块盘右侧会实时显示状态，见下方「常驻」说明）。
3. **受控风扇**：勾由硬盘温度接管的风扇（比如机箱风扇 / SYS_FAN2）。**这里至少勾一个**，否则等于没接管，面板会弹橙色提示。
4. **温控曲线**：设 4 个值——
   - 开转温度（盘到这温度开始转，如 40°C）
   - 全速温度（到这温度拉满，如 60°C）
   - 开转占空比（最低转速百分比，如 30%）
   - 全速占空比（如 100%）
   - 恢复自动温度（降到这以下就把风扇交还系统自动控温，如 35°C——带滞回，避免临界抖动）
5. 可选「曲线编辑器」自定义「温度→PWM」多点曲线（可一键套用静音/均衡/性能预设）。
6. 点 **「保存配置」**，盯一下按钮旁提示是否出现「已保存 ✓」。
7. 可选「监控盘连续无读写满 N 分钟也停转风扇」：勾上后，监控盘**即使没进休眠态**，只要连续 N 分钟没有任何读写（底层按磁盘扇区读写计数判断），风扇照样停。它和「盘休眠」是**二选一**关系——满足任一就停。默认 N=5 分钟，可设 1–120 分钟。这个选项专门解决「明明设了休眠、风扇却一直空转」的情况（有些机器硬盘从不报休眠态，旧版就只能干等）。

**关于「常驻」—— 这是这次修复的重点**

每块监控盘右侧会显示三种状态之一：

| 显示 | 含义 |
|------|------|
| **温度（如 44°C）** | 这块盘是普通机械盘，能正常休眠，正显示实时温度 |
| **休眠** | 盘已经停转省电了 |
| **常驻** | 这块盘是 **SAS 企业盘**或**固态盘(SSD)**，厂商为数据安全**锁死了不让停转**，所以它永远不参与「全部休眠→停风扇」的判断 |

**那到底要不要勾 SAS/固态盘？** 两种选法，停转功能都正常：

- **勾上（推荐，散热更周全）**：这块盘的温度会**参与风扇曲线控速**——SAS/固态一发烧，受控风扇就提速给它散热。尤其 SAS 企业盘本身容易跑暖，勾上更稳。
- **不勾**：它完全不监控、不查温度、也不影响停转功能（反正天生被排除）。代价是它发烫时风扇不会为它专门提速，得靠机箱整体风道。

> 一句话：**勾＝让它的热量去管风扇；不勾＝当它不存在。** 停转功能两种都不受影响。

为什么要这么设计？因为「硬盘全部休眠才停风扇」这条规则，一旦混了 SAS/SSD 盘就**永远等不到它们睡**（它们天生不睡），等于把整个停风扇功能卡死。所以面板把 SAS/SSD 直接排除在「判断是否该停转」之外：

- **只有能睡的机械盘全都睡了**，风扇才停 → 省电。
- 但安全阀还在：如果某块 SAS/SSD 盘**发烫超过开转温度**，风扇照样转给它散热，不会不管它。
- 界面上 SAS/SSD 盘标「常驻」，让你一眼知道它不参与休眠判断。

> 实战例子：你这台机器 `sde` 其实是一块 SATA 固态盘（rotational=0），之前一直被当机械盘、悄悄堵着停转功能；现在正确识别成「常驻」，机械盘（sdc/sdd）睡了风扇就能停。

**B. 主板/CPU 温控（sys_temp）—— 看 CPU/主板温度调风扇**

跟硬盘温控对称配置，只是温度来源换成 CPU 封装温度或主板温度。两套可以各管各的风扇，互不打扰。

想要更细的玩法——比如两台风扇跟**同一温度**却用**不同曲线**，见下方 7.2.5 逐风扇温度联动控速。

#### 7.2.5 逐风扇温度联动控速（进阶玩法）

如果你只用「全局硬盘温控」或「全局 CPU 温控」，上面两套曲线已经够。但有些机器想更细：比如机箱里两台硬盘风扇都想跟着硬盘温度走，可你希望**一台在 30–45°C 慢慢提速、另一台等到 45–60°C 才猛吹**，或者干脆一台跟硬盘、一台跟 CPU。这种「同温源、不同曲线」的需求，就用**逐风扇温度联动控速**。

**怎么设：**
1. 在风扇卡片里找到「温度联动控速」区，点开。
2. **温度源**下拉选一个：
   - **关闭**：这台风扇不单独联动，沿用全局面板默认曲线（或纯手动）。
   - **硬盘**：跟「硬盘温控」盯的那组盘的最高温度走（和全局硬盘温控共用同一批监控盘 / 休眠 / 空闲停转设置）。
   - **CPU** / **主板**：分别跟 CPU 封装温度 / 主板温度走。
3. 填这条风扇**自己的**曲线：开转温度 / 全速温度 / 开转占空 / 全速占空 / 恢复自动温度（含义和 6.2 的 A 部分一样，也能用曲线编辑器画多点曲线）。
4. 点「保存」。卡片上会实时显示「计算目标 X%」，告诉你这台风扇此刻会去到多少速。

**几个要点：**
- **同温源、不同曲线完全支持**：两台都选「硬盘」、各自曲线不同，互不影响。
- **默认推荐值**会按你选的源自动填好（硬盘源 / CPU 源 / 主板源各有一套合理起点），不想细调直接存就行。
- **低于开转温度即停转（强制 0%）**：勾选后，这台风扇在温度没到「开转温度」之前会**彻底停转**（写 0%，而不是交还给主板自动控温）。适合「平时靠静音扇、高温才启暴力扇」的机器——把暴力扇的开转温度设高、并勾上这一项，就能做到「不到那个温度它绝不转」。注意：只有明确读得到温度、且温度低于开转温度时才强制停；读不到温度（传感器异常）会保守地交还系统自动，不会在未知高温下把风扇熄火。
- **向后兼容**：你从没碰过「逐风扇」区的风扇，继续按上面的全局面板走，老配置一个字都不用改。
- 配置存进 `fan_rules.json`（同样在 `/vol1/@appdata/com.dashboard.nasdash/`），重启不丢。

#### 7.3 与 FanControlServer 的共存（安全接管）

飞牛系统自带一个风扇服务叫 **FanControlServer（FCS）**。两套调速器同时写同一个 PWM 通道会抢控制权、转速乱跳。nasdash 的做法是**安全接管**：

- 当 nasdash 正在主动控速（手动/温控/规则接管了某风扇）时，自动先停掉 FCS；
- 当这些风扇**全部交还系统自动控温**后，自动把 FCS 拉起来。
- 你**没开任何控速**时，nasdash 完全不碰 FCS，零打扰。

> 纠结要不要杀 FCS？**不用手动杀**。安全接管已自动处理：nasdash 控速时停 FCS、全交还后自动拉起。v2.0.5 起面板不再提供 FCS 一键开关，需要永久禁用 / 恢复时用 SSH 执行 `systemctl disable/enable pwm-fancontrol`。

#### 7.4 风扇控制接管开关（一键接管 / 交还）

2.0 新增一个**总开关**，决定「风扇调速归谁管」：

- **位置**：风扇控制页顶部的「接管风扇控制」开关。
- **打开（接管）**：nasdash 按你设的档位 / 温控曲线来控所有风扇；此时飞牛自带的 FCS 会被停掉（见 7.3 安全接管）。
- **关闭（交还）**：nasdash 把风扇调速交回飞牛原服务，界面不再干预，FCS 自动拉起。
- **防卡死保护**：点完按钮界面立即响应、不会卡住转圈；万一后端没回，也会超时自动复位，不会出现「点了没反应、开关动不了」的情况。
- 关掉接管后，风扇不再因 nasdash 的残留逻辑狂转，完全交给飞牛原生控温。

> 和 6.3 的区别：6.3 讲的是 nasdash 与飞牛 FCS「怎么不打架」；这节的开关是你**主动选择**要不要让 nasdash 来管。默认建议：想精细控温就开，想省心交给飞牛就关。

#### 7.5 风扇页显示「未检测到可调控风扇 / 可控 0」？先装 ite-it87 驱动

如果你打开风扇控制页，顶部写着「可控风扇 0」、下面提示「未检测到可调控风扇」，**先别急着怀疑面板**——这十有八九不是 nasdash 的 bug，而是你的系统还没给风扇装「调速驱动」。

nasdash 只能接管系统已经暴露出来的调速接口。打个比方：飞牛把风扇转速「读出来给你看」是一回事，把「让第三方软件去调它转速」的开关「打开」是另一回事。nasdash 要的是后者那个开关（系统里叫 `/sys/class/hwmon/.../pwmN` 文件），开关没开，它就接管不了。

怎么办，三步：

1. 打开飞牛**应用中心 → 搜索 `ite-it87`** 并安装。这是一个社区维护的传感器驱动，认 **ITE IT87/IT86 系列**芯片（很多 NAS/主板用它管风扇），装完系统就会把 PWM 调速接口暴露出来。
2. 如果你用的是 **Nuvoton NCT 系列**芯片（比如常见的消费级主板 B360/B365，作者自己的机器就是 NCT6797D），系统一般**已经自带** `nct6775` 驱动，不用额外装；万一没有，可以手动跑 `modprobe nct6775` 加载。
3. 装完驱动**重启一下 nasdash**（应用中心里把 nasdash 停掉再开，或者直接重启 NAS），回到风扇页刷新，PWM 通道就会自动列出来，直接接管调速即可。

> **关键点**：nasdash 是「枚举系统里所有风扇接口、不挑具体芯片」的。所以装好对应驱动后**不用重装 nasdash**，刷新页面就生效——它不是写死了只认某一款主板。

不同结果的对照：

| 你看到的 | 说明 |
|----------|------|
| 装了 ite-it87 后风扇出现了 | 你的风扇控速芯片是 ITE/IT86 系列，驱动一装接口就露出来了，nasdash 自动接管 |
| 装了还是 0 | 你的硬件风扇控速芯片不在 ite-it87 支持范围。典型如部分 **N150 平台**走 PCH/EC 直控，飞牛自家只把转速读出来显示、没把调速接口开放给系统，第三方（包括 nasdash）都接管不了，只能等飞牛官方哪天开放接口 |
| 飞牛「资源管理」能显示风扇转速，nasdash 却显示 0 | 完全正常——飞牛自家读转速走它内部接口；nasdash 要的是标准调速接口，两者不是一回事，别被「飞牛能显示」误导成「nasdash 该也能控」 |

### 9. 端口占用

打开方式：左侧边栏「其他」分组 → 🔌 端口占用。它列出 NAS 上**所有正在被监听的端口**，并告诉你**是谁在占**。

**每一列是什么意思**

| 列 | 说明 |
|---|---|
| 协议 | TCP / UDP |
| 本地地址:端口 | 听在哪个地址、哪个端口上。地址太长会被省略，**鼠标悬停能看完整** |
| 状态 | 「监听中」＝TCP 端口开好了、等人来连；「未连接」＝UDP 端口绑好了、可以收包（UDP 本来就没有"建立连接"这回事） |
| 进程 / PID | 占用端口的程序名和它的编号。这里显示**「内核」**表示该端口由系统内核自己持有（如 NFS 文件共享），读不到程序名，属正常现象 |
| 来源 | 三选一：**应用**（飞牛应用中心装的，显示应用真名 + 它自己的图标）/ **容器**（Docker 容器映射出来的）/ **系统**（飞牛自带服务，配中文说明，如「飞牛文件共享 (SMB)」「SSH 远程登录」） |
| 操作 | 「释放」按钮 |

**地址后面那个小徽章（对外 / 容器网 / 仅本机）**

它回答的是「**这个端口能被谁连上**」，分三档：

| 徽章 | 含义 | 举例 |
|---|---|---|
| **对外** | 局域网里任何一台设备都能连 | 文件共享 445、Web 管理后台 |
| **容器网** | 只有 NAS 自己和它上面的容器内部能连，局域网里其他电脑连不上 | `172.17.x.x` 这类容器网地址 |
| **仅本机** | 只有 NAS 自己能连，外面谁都进不来 | nasdash 自己的 9800、数据库的 5432 |

**怎么找东西**

- **来源分布**：标题旁边常显一行「应用 10 · 容器 16 · 系统 48」，一眼看出这台机器上各种来源分别占了多少个端口。
- **筛选下拉**：只看「应用 / 容器 / 系统」里的某一类。
- **搜索框**：端口号、进程名、应用名（**能搜中文**，如「飞邮」）、来源说明，任意命中即可。
- 同一个端口被多个程序占用时，会**分行全部列出来**（后续行标「↳ 同一端口（2/3）」），不会被合并掉、也就不会漏。

**释放端口（有破坏性，用前想清楚）**

- 点「释放」→ 弹窗会列出端口 / 进程 / PID / 来源，让你确认是不是真的要关。
- 确认后向该进程发送 **SIGTERM**（温和的「请你退出」，不是强杀）。
- **系统关键进程杀不掉**：nasdash 自身、PID 1、systemd、dockerd、sshd、nginx 等由后端直接拒绝，点了也不会生效。
- 若一个端口有**多个**占用者，杀掉其中一个并不会把端口空出来——弹窗会提醒你「还有 N-1 个进程在监听」。
- 想关的是飞牛自带服务（如 SMB 文件共享、SSH 远程登录）时务必想清楚：关掉之后，对应的功能会立刻不可用。

### 10. 控制与自动化（告警 + 通知 + 健康报告）

打开方式：左侧边栏「其他」分组 → 🔔 控制与自动化。这一页有**四张卡片**，从上到下依次是：

**① 活动告警（看有没有事）**
- 每 **15 秒**自动刷新，不用手动点。
- 红色 = 严重问题（如硬盘健康异常）；橙色 = 警告（如温度偏高）。每条显示「标题 — 详情」。
- 一切正常时显示"当前无活动告警 ✓"，说明 NAS 状态良好，可以放心。

**② 告警规则（设警戒线）**
就像给 NAS 设"火警温度"，超过就报警：

| 规则 | 默认值 | 可调范围 | 说明 |
|---|---|---|---|
| CPU 最高温度 | 85°C | 40~100 | CPU 超过这个温度触发告警 |
| 主板/芯片组最高 | 75°C | 40~100 | 主板上芯片的温度 |
| 硬盘最高温度 | 60°C | 30~90 | 任意一块盘超过就报 |
| 内存占用上限 | 90% | 50~100 | 内存用到这个比例就报警 |

- 顶部是「启用告警监控」**总开关**；下面「温度告警」「硬盘健康告警（SMART pre-fail / 异常）」是两个独立开关，想关哪个关哪个。
- **改完一定要点「保存配置」**，不然重启就丢了（设置存在 NAS 本地，见第四章）。
- 想确认通知能不能发出去，点「**发送测试通知**」试一发，比瞎等靠谱。

**③ 通知渠道（报警了通知谁）**
- **面板内提示**（默认开）：告警记录在应用里，始终保留、随时能翻。
- **Telegram**：填 Bot Token + Chat ID。Token 在 Telegram 里找 @BotFather 创建机器人拿到；Chat ID 找 @userinfobot 发条消息就能查到。
- **Bark**：填推送地址（`https://api.day.app/你的Key`）。iPhone 装 Bark 应用，打开就能看到自己的 Key。
- **邮件**：填 SMTP 服务器（如 QQ 邮箱 `smtp.qq.com`）、端口（默认 465）、邮箱账号、**授权码**（注意不是登录密码——要在邮箱设置里开启 SMTP 服务后生成）、接收地址。
- 哪个渠道的开关没勾就不推送；填好记得「保存配置」。

**④ 一键健康报告（排查问题用）**
- **导出 JSON**：所有硬件状态 + 活动告警的原始数据，适合留档。
- **导出 HTML 报告**：排版好的报告，里面还带运行日志（按错误/警告分级），适合给懂行的人看。
- **查看运行日志**：遇到 bug 或异常时点它，弹窗里错误/警告会**置顶标红**——先自己看一眼确认情况，再决定要不要复制发给开发者，不用整页截图。

**📘 操作手册**：左侧导航「其他」分组下（🔔 控制与自动化下方）有「📘 操作手册」一项，点它会在右侧面板里**就地展开**这份文档（不跳新页面、不离开应用），**离线可读、不用联网**。里面就是你现在看的这份大白话教程。

## 四、配置存在哪？重启会不会丢？

所有设置（风扇名称、温控曲线、硬盘温控开关、受控风扇列表等）都持久化在：

```
/vol1/@appdata/com.dashboard.nasdash/
```

这是飞牛的系统数据盘，**重启不丢**。各配置文件：

| 文件 | 内容 |
|------|------|
| `fan_mode.json` | 风扇手动/自动档位 |
| `fan_disk_temp.json` | 硬盘温控配置 |
| `fan_sys_temp.json` | 主板/CPU 温控配置 |
| `fan_labels.json` | 风扇自定义名称/隐藏 |
| `fan_curve_*.json` | 自定义曲线 |
| `fan_rules.json` | 逐风扇温度联动控速规则 |
| `alert_*.json` | 告警规则与通知渠道 |

> **重要修复（本版已修）**：早期版本有个隐蔽 bug——温控配置「存得进、读不出」，导致勾选在刷新/重启后丢失、温控实际不生效。现已修复，**保存后刷新/重启配置都还在**。如果你之前遇到「勾好的设置没了」，升级这版后就没事了。

## 五、常见问题排查

| 现象 | 是不是 bug | 怎么办 |
|------|-----------|--------|
| 风扇显示「无转速信号」 | 不是 | 该通道风扇没接测速线（3针/缺 tach）或空接口。仍能调速，点「隐藏」收起即可 |
| hwmon 编号跨重启变化 | 不是 | 内核给控制器分配的 `hwmonN` 会漂。面板已按通道序号(idx)命中真实通道，不影响调速，重启不乱 |
| 名字显示「it8772 风扇 N」 | 不是 | 旧 FanControlServer 配置残留标签。风扇卡片里改名即可 |
| 手动调速后停目标值不回弹 | 不是 | 设计行为：拖动即手动控制。点「恢复自动」才交还系统 |
| 滑块最低可到 0%（停转） | 不是 | 手动调速下限已放开到 0%，想完全停转选「停转」档位即可，不再卡在 10% |
| 勾好的温控设置重启没了 | **曾是 bug，已修** | 升级到含修复的版本即可；若仍丢，检查 `/vol1/@appdata/.../fan_disk_temp.json` 是否生成 |
| 启用硬盘温控但风扇不动 | 多半是没勾「受控风扇」 | 去「受控风扇」勾至少一个风扇再保存；面板会橙色提示 |
| 混了 SAS/SSD 盘，休眠停转不生效 | 已修复 | 升级后 SAS/SSD 标「常驻」自动排除，机械盘全睡即可停转 |
| 想让两台风扇跟同一温度却各用不同曲线 | 不是 bug | 用风扇卡片里的「温度联动控速」：两台都选「硬盘」源、各自填不同曲线即可，见 7.2.5 |
| 风扇控制页显示「未检测到可调控风扇 / 可控 0」 | 通常不是 | 系统没装风扇调速驱动：应用中心搜 `ite-it87` 安装（ITE/IT86 芯片）；NCT 系列一般自带 `nct6775`。装完重启 nasdash 刷新即出，详见 7.5 |

## 七、一句话总结操作顺序

1. 装好 → 桌面图标打开。
