# nasdash 操作手册（大白话版）

本手册讲清楚 nasdash 这面板**怎么用、每个开关干什么、遇到问题怎么查**。不用懂 Linux 命令，照着点就行。

> 本手册**仅对应当前代码版本 v1.9.9**。以后 nasdash 升级出新版本，本手册会同步更新到对应版本号，老版本用户请回 GitHub Releases 找对应 tag 的手册查看。功能以你实际界面为准，个别主板/风扇命名可能不同，属正常现象。

**本版本新增了什么（v1.9.9 新增）**

==**① 修复温度墙高温显示回归（修复）**==
==  v1.9.5 起温度墙前端加了一道过滤，把 100°C 以上的温度探头直接隐藏，导致部分机器本该看到的高温热（红色预警）看不到，只剩 80 几度的其它探头。现已恢复：只过滤真正离谱的极端值（150°C 以上），正常的 100+ 高温会照常显示并标红。==

## 一、先搞明白：nasdash 是什么

nasdash 是飞牛OS（fnOS）上的一个**硬件监控面板**，把原本要 SSH 敲命令才能看的硬件状态，做成网页一眼看完：

- 你有什么硬件（CPU/内存/主板/显卡/阵列卡/网卡）
- 硬盘健不健康、多少度
- 风扇转多快、能不能调速
- 阵列卡/Raid 状态、存储卷用了多少
- Docker 容器在不在跑
- 温度高了会不会自动报警

一句话：**它是你 NAS 的「仪表盘 + 风扇遥控 + 报警器」三合一**。

---

## 二、怎么打开

1. 在飞牛OS **应用中心**装好 nasdash（手动安装 `nasdash.fpk`）。
2. 桌面会出现「NAS硬件监控」图标，点开即进入。
3. 面板经飞牛**统一网关**暴露，**要先登录飞牛账号**才能看。
4. 外部访问请走飞牛自带的远程访问 / 反代，**不要直接把 9800 端口暴露到公网**。

> 小提示：面板每 30 秒左右自动刷新（系统资源页有「自动刷新」开关）。

## 三、七个模块逐一讲解

左侧边栏共七个模块，下面挨个说。

### 1. 硬件配置检测（首页仪表盘）

进面板第一眼就是它，单页总览，按硬件分卡片平铺：

- **顶部状态栏**：阵列卡 / 硬盘 / Docker / 系统负载一屏速览。
- **处理器**：型号、核心/线程数、**实时频率**、**CPU 温度**、当前负载占用。
- **显卡**：独立成卡。核显、独显分别列出，每张显示 **型号、PCIe（地址与通道上下合并显示，含中文明文说明）、驱动（含版本）、显存容量、核心频率、显存频率、显存位宽、GPU 温度、功耗** 等项。驱动行统一显示「模块名 + 版本」：NVIDIA 用 `nvidia-smi` 的官方驱动版本号（如 `nvidia 535.86.05`）；AMD/Intel 开源驱动（amdgpu/i915）随内核发布、无独立版本号，飞牛精简系统也未预装 `modinfo`，故显示其所在**内核版本**（如 `amdgpu 6.18.18`）。独显（NVIDIA）通过 `nvidia-smi` 取实时显存/频率/位宽/温度/功耗；AMD 独显通过 `amdgpu` 驱动的 sysfs 接口（`pp_dpm_sclk/mclk` 当前档，回退 `hwmon` 的 `freq1/freq2_input`）读核心频率与显存频率，温度与功耗（瞬时 `power1_input`、上限 `power1_cap`）取 `amdgpu` hwmon，显存容量取 `lspci` 显存区间；还读 `lspci -vvv` 显示**当前实际跑在 PCIe 几代、几条通道**（如「PCIe 4.0 x16（协商 x16，上限 x16）」）；若被主板降到 x8 会标橙字「未跑满」，一眼看出卡没插满速。**功耗**一行同时显示「瞬时功耗（W） / 上限（W）」，接近上限（≥85%）变橙、≥95% 变红，一眼看出卡是不是撞了功耗墙被限速。**AMD 显存位宽** amdgpu 没有标准接口暴露，用「设备 ID → 位宽查表」解决（如 RX 6600 XT 设备号 0x73ff = Navi 23 = 128 位、RX 6800 系列 0x73bf = 256 位），查表覆盖 RX 5000/6000 常见型号；未收录的型号会灰字提示「暂未识别」。核显读得到核心频率（如 350 MHz），温度取 CPU 同封装温度、显存标「共享系统内存」、PCIe 项标「集成于 CPU，不占用独立 PCIe 插槽」、功耗标「核显与 CPU 共用电源，未单独统计」。**核显本就没有独立显存**，所以「显存频率 / 显存位宽」会直接写明原因（如「核显与 CPU 共用内存，无独立显存频率」），而不是显示一个没意义的 0 或「—」。只插独显时主板 BIOS 常自动禁用核显，这条也会提示出来，不会凭空消失。
- **内存**：按主板插槽画成若干小方块（已插的实色、空槽灰显），并标出是**单通道还是双通道**；品牌取自 SPD 直读，区分「模组厂」和「颗粒厂」（比如模组是某品牌、颗粒是三星），还会标颗粒厂。
- **主板型号**：由主板 DMI 信息自动读取（品牌 / 型号 / 版本 / BIOS / 芯片组）；DMI 读不到时回退显示芯片组推断，并注明「BIOS 未写入主板信息」。
- **系统信息**：已运行多久、**交换分区（swap）用了多少**等。
- **温度墙**：主板所有温度测点集中成一张彩色小卡片墙，绿=正常 / 橙=偏高 / 红=危险；自动过滤掉 0°C、负温这类无效测点，不会再用一堆 0 度填满屏幕。英文代号（如 `AUXTIN0`、`CPUTIN`、`SYSTIN`）已自动翻译成中文，鼠标悬停在小卡片上还能看到原始英文名，方便核对。
- **网络**：只列真实网卡（已自动过滤 ovs、veth、docker 等虚拟接口），显示 IP / 协商速率 / 连接状态，以及实时上下行流量。
- **阵列卡 & 磁盘**：卡型号 + 物理盘，SMART 健康速览。

> 没看懂的字段不用管，这一页就是「看个全貌」，颜色异常再点进去细看。

### 2. 阵列卡

面板用 `lspci` 自动识别你插的是哪种卡，分三种情况显示，**不会瞎报**：

- **MegaRAID 阵列卡**（如 LSI 9271-8i，RAID/IR 模式）：显示型号 / 序列号 / SAS 地址 / 固件 / BIOS / 驱动 / PCI 地址、CacheVault 缓存电池状态、**ROC 芯片温度**、JBOD 物理盘列表（槽位 / 品牌 / 型号 / 接口 / 容量 / 状态 / 转速）。
- **HBA 直通卡**（如 LSI 9300，IT 模式）：显示卡型号 + 「IT 直通模式」说明，额外显示 **HBA 芯片温度**。直通卡下的盘由系统直接识别成 `/dev/sdX`，温度去「硬盘 SMART」标签页看。
- **纯 SATA 主板**（没独立阵列卡）：提示「无独立阵列卡」，温度请见「硬盘 SMART」。

> **双磁臂（双执行器）硬盘**：阵列卡会把每个执行器当独立盘暴露（比如各 7T），面板在阵列卡页显示整盘标称容量（如 14T）并标注每执行器容量——这是正常的，不是 bug。

### 3. 硬盘 SMART

所有硬盘的健康体检页：

- 同时支持 **SAS/SCSI 盘** 和 **SATA/ATA 盘**。
- 自动识别品牌与特性（希捷/西数/东芝/三星，双磁臂盘带徽章）。
- 健康状态：OK/PASSED 标绿，异常标红。
- 温度 / 通电时长 / 坏块计数 / 错误计数。
- **机械盘显示真实转速**（7200 rpm / 5400 rpm）；**SSD 显示「固态(SSD)」**。
- SATA 盘额外显示 Reallocated / Pending / Uncorrectable / UDMA CRC 等告警计数。

> 这块盘到底是不是 SSD，面板靠内核 `rotational` 值判断（0=固态 / 1=机械），准的。

### 4. 系统资源

- **CPU**：型号 / 核心 / 线程 / 频率 / 负载。
- **内存 / Swap**：使用率。
- **温度传感器**：分类显示（CPU 各核心 / 芯片组 PCH / 主板 / ACPI），CPU 温度带 max/crit 上限。
- **风扇转速**：读转速 + PWM 占空比。**0 RPM 的停转风扇会标红**。控制模式从 sysfs 读（0=关闭 / 1=手动 / 2=自动温控）。
- **电压**：+3.3V / 待机 / CMOS 电池等。

### 5. 历史趋势

- 磁盘 I/O（读/写速率）折线图，可切 **24 小时 / 7 天 / 30 天**。
- 数据存在本地 SQLite，**重启不丢**，自动保留 30 天。

### 6. 风扇控制（重点模块）

这是最能「动手」的模块。三块内容：**预设调速 / 温控曲线（含逐风扇联动）/ 安全接管**。

#### 6.1 预设档位与自定义

- 预设档位（默认 / 全速 / 停转(0%) / 10%…90%）一键调速，卡片实时显示 RPM 与占空比。
- 每个风扇可**网页改名**（如「CPU 风扇」「机箱风扇」）和标供电电压（12V / 5V / 未知），按安装实例持久化。
- **同名风扇自动合并**：如果你给多台风扇设了**相同名称**，面板会判定它们是同一物理风扇（主板把同一个风扇识别成了两张卡），自动**合并成一张卡**，改名/隐藏/调速会**同步到全部同名通道**——专门解决「明明一个风扇、却显示成两张卡、改一个名另一个不动」的问题。想让它们各自独立，只要设成不同名称即可。
- 手动调速下限放宽到 **0%（停转）**；点「恢复自动」即把风扇交还主板/内核自动控温。

#### 6.1b 调速方式：PWM 还是 DC（风扇根本不听话时先看这里）

风扇卡片标题栏有个「**PWM 调速 / DC 调速**」的下拉框，它说的是**主板这个插座用什么方式来控速**：

| 方式 | 对应风扇 | 原理（大白话） |
|------|---------|--------------|
| **PWM** | 4 针风扇 | 多出来的第 4 根线是专门的「调速信号线」，主板按这根线的指令控速，供电电压始终是满的 |
| **DC** | 3 针风扇 | 没有信号线，只能靠**调高调低供电电压**来控速，电压低转得慢 |

**为什么要管这个？** 如果你插的是 3 针风扇，而主板这个口被设成了 PWM，风扇收不到任何调速指令，就会**一直全速狂转**——不管你在面板上怎么调都没用。这是「调速不生效」最常见的原因，比软件 bug 常见得多。这时把该口切成 **DC** 就好了。

**怎么判断自己是哪种？** 看插头上的针数：4 针是 PWM，3 针是 DC。也可以直接试——调到 30% 看风扇转速有没有降，没降八成就是插错了方式。

**⚠️ 能不能切，主板说了算。** 很多主板只有一两个口（一般是 CPU_FAN、PUMP）做了 PWM/DC 双模式电路，剩下的口出厂就焊死只能走 PWM。切不动的口，面板会直接告诉你「该接口硬件只支持 PWM 模式，无法切换（主板限制，非软件问题）」，并把下拉框弹回真实状态——**不会假装切成功**。碰到这种情况只有两条路：进 BIOS 找找有没有对应选项，或者换一把 4 针风扇。

**切到 DC 之后注意：** DC 是靠降电压控速的，电压太低风扇可能**转不动或者干脆停了**（PWM 就不会，它电压始终是满的）。所以 DC 模式下的卡片会多出一行蓝色提示。如果发现风扇低速时抖动、启动不起来，把最低转速调高一点（比如从 20% 提到 35%），或者干脆切回 PWM。

#### 6.1c 转速一直显示 0？勾一下「无反馈线」

有些风扇（尤其是机箱自带的、或者跟阵列卡/硬盘笼一起送的）是 **2 针或 3 针**的，线上**没有转速反馈线**。这种风扇转得好好的，但主板读不到它转多少，面板上就一直显示 `0 转`——看着像坏了，其实完全正常。

风扇卡片标题栏里有个「**无反馈线**」的勾选框，勾上再点「保存标注」，这一栏就不再显示刺眼的 0，改成显示「**— 无反馈线（正常）**」，也不会再被当成故障风扇。

**勾上之后还有个附带好处：** 如果这口同时还是 **PWM 调速**，卡片会弹一条橙色警告——

> ⚠️ **这口的百分比可能不起作用。**没有反馈线的风扇通常也没有 PWM 信号线，收不到调速指令，供电一直给满，很可能**始终全速转**，面板上调多少都没反应。

这条提示能帮你省下大把排查时间：**转速读不到**和**调速调不动**，在 2/3 针风扇上往往是同一个原因——线不够。解决办法就是上面 6.1b 讲的：切 DC、进 BIOS、或者换 4 针风扇。

**注意区分两种「读不到转速」：**

| 情况 | 面板显示 | 该怎么办 |
|------|---------|---------|
| 确实接了 2/3 针风扇 | 勾「无反馈线」后显示「— 无反馈线（正常）」 | 正常，不用管 |
| 这口压根没插风扇 | 不勾，显示「— 无转速信号」 | 点「隐藏」把这个空通道收起来 |

#### 6.2 两套独立温控曲线

面板能按温度自动调风扇，且**两套互不干扰、可分别接管不同风扇**：

**A. 硬盘温控（disk_temp）—— 看盘的温度调风扇**

适用场景：你想让「硬盘散热风扇」跟着硬盘温度走（盘热就多吹，盘凉就少吹）。

配置步骤：
1. 勾 **「启用硬盘温控」**。
2. **监控硬盘**：勾你想盯的盘（界面每块盘右侧会实时显示状态，见下方「常驻」说明）。
3. **受控风扇**：勾由硬盘温度接管的风扇（比如机箱风扇 / SYS_FAN2）。**这里至少勾一个**，否则等于没接管，面板会弹橙色提示。
4. **温控曲线**：设 4 个值——
   - 开转温度（盘到这温度开始转，如 40°C）
   - 全速温度（到这温度拉满，如 60°C）
   - 开转占空比（最低转速百分比，如 30%）
   - 全速占空比（如 100%）
   - 恢复自动温度（降到这以下就把风扇交还系统自动控温，如 35°C——带滞回，避免临界抖动）
5. 可选「曲线编辑器」自定义「温度→PWM」多点曲线（可一键套用静音/均衡/性能预设）。
6. 点 **「保存配置」**，盯一下按钮旁提示是否出现「已保存 ✓」。
7. 可选「监控盘连续无读写满 N 分钟也停转风扇」：勾上后，监控盘**即使没进休眠态**，只要连续 N 分钟没有任何读写（底层按磁盘扇区读写计数判断），风扇照样停。它和「盘休眠」是**二选一**关系——满足任一就停。默认 N=5 分钟，可设 1–120 分钟。这个选项专门解决「明明设了休眠、风扇却一直空转」的情况（有些机器硬盘从不报休眠态，旧版就只能干等）。

**关于「常驻」—— 这是这次修复的重点**

每块监控盘右侧会显示三种状态之一：

| 显示 | 含义 |
|------|------|
| **温度（如 44°C）** | 这块盘是普通机械盘，能正常休眠，正显示实时温度 |
| **休眠** | 盘已经停转省电了 |
| **常驻** | 这块盘是 **SAS 企业盘**或**固态盘(SSD)**，厂商为数据安全**锁死了不让停转**，所以它永远不参与「全部休眠→停风扇」的判断 |

**那到底要不要勾 SAS/固态盘？** 两种选法，停转功能都正常：

- **勾上（推荐，散热更周全）**：这块盘的温度会**参与风扇曲线控速**——SAS/固态一发烧，受控风扇就提速给它散热。尤其 SAS 企业盘本身容易跑暖，勾上更稳。
- **不勾**：它完全不监控、不查温度、也不影响停转功能（反正天生被排除）。代价是它发烫时风扇不会为它专门提速，得靠机箱整体风道。

> 一句话：**勾＝让它的热量去管风扇；不勾＝当它不存在。** 停转功能两种都不受影响。

为什么要这么设计？因为「硬盘全部休眠才停风扇」这条规则，一旦混了 SAS/SSD 盘就**永远等不到它们睡**（它们天生不睡），等于把整个停风扇功能卡死。所以面板把 SAS/SSD 直接排除在「判断是否该停转」之外：

- **只有能睡的机械盘全都睡了**，风扇才停 → 省电。
- 但安全阀还在：如果某块 SAS/SSD 盘**发烫超过开转温度**，风扇照样转给它散热，不会不管它。
- 界面上 SAS/SSD 盘标「常驻」，让你一眼知道它不参与休眠判断。

> 实战例子：你这台机器 `sde` 其实是一块 SATA 固态盘（rotational=0），之前一直被当机械盘、悄悄堵着停转功能；现在正确识别成「常驻」，机械盘（sdc/sdd）睡了风扇就能停。

**B. 主板/CPU 温控（sys_temp）—— 看 CPU/主板温度调风扇**

跟硬盘温控对称配置，只是温度来源换成 CPU 封装温度或主板温度。两套可以各管各的风扇，互不打扰。

想要更细的玩法——比如两台风扇跟**同一温度**却用**不同曲线**，见下方 6.2.5 逐风扇温度联动控速。

#### 6.2.5 逐风扇温度联动控速（进阶玩法）

如果你只用「全局硬盘温控」或「全局 CPU 温控」，上面两套曲线已经够。但有些机器想更细：比如机箱里两台硬盘风扇都想跟着硬盘温度走，可你希望**一台在 30–45°C 慢慢提速、另一台等到 45–60°C 才猛吹**，或者干脆一台跟硬盘、一台跟 CPU。这种「同温源、不同曲线」的需求，就用**逐风扇温度联动控速**。

**怎么设：**
1. 在风扇卡片里找到「温度联动控速」区，点开。
2. **温度源**下拉选一个：
   - **关闭**：这台风扇不单独联动，沿用全局面板默认曲线（或纯手动）。
   - **硬盘**：跟「硬盘温控」盯的那组盘的最高温度走（和全局硬盘温控共用同一批监控盘 / 休眠 / 空闲停转设置）。
   - **CPU** / **主板**：分别跟 CPU 封装温度 / 主板温度走。
3. 填这条风扇**自己的**曲线：开转温度 / 全速温度 / 开转占空 / 全速占空 / 恢复自动温度（含义和 6.2 的 A 部分一样，也能用曲线编辑器画多点曲线）。
4. 点「保存」。卡片上会实时显示「计算目标 X%」，告诉你这台风扇此刻会去到多少速。

**几个要点：**
- **同温源、不同曲线完全支持**：两台都选「硬盘」、各自曲线不同，互不影响。
- **默认推荐值**会按你选的源自动填好（硬盘源 / CPU 源 / 主板源各有一套合理起点），不想细调直接存就行。
- **低于开转温度即停转（强制 0%）**：勾选后，这台风扇在温度没到「开转温度」之前会**彻底停转**（写 0%，而不是交还给主板自动控温）。适合「平时靠静音扇、高温才启暴力扇」的机器——把暴力扇的开转温度设高、并勾上这一项，就能做到「不到那个温度它绝不转」。注意：只有明确读得到温度、且温度低于开转温度时才强制停；读不到温度（传感器异常）会保守地交还系统自动，不会在未知高温下把风扇熄火。
- **向后兼容**：你从没碰过「逐风扇」区的风扇，继续按上面的全局面板走，老配置一个字都不用改。
- 配置存进 `fan_rules.json`（同样在 `/vol1/@appdata/com.dashboard.nasdash/`），重启不丢。

#### 6.3 与 FanControlServer 的共存（安全接管）

飞牛系统自带一个风扇服务叫 **FanControlServer（FCS）**。两套调速器同时写同一个 PWM 通道会抢控制权、转速乱跳。nasdash 的做法是**安全接管**：

- 当 nasdash 正在主动控速（手动/温控/规则接管了某风扇）时，自动先停掉 FCS；
- 当这些风扇**全部交还系统自动控温**后，自动把 FCS 拉起来。
- 你**没开任何控速**时，nasdash 完全不碰 FCS，零打扰。

面板底部还有**一键永久禁用/恢复 FCS** 的开关（显示当前状态）：
- 永久禁用 = `stop` + `disable`（重启不复活）；
- 恢复 = `enable` + `start`。
- 都不用 SSH 敲命令。

> 纠结要不要杀 FCS？**不用手动杀**。只用一个就够：要么用 nasdash 管，要么在面板一键永久禁用 FCS 让系统原生控温，二选一。

## 四、配置存在哪？重启会不会丢？

所有设置（风扇名称、温控曲线、硬盘温控开关、受控风扇列表等）都持久化在：

```
/vol1/@appdata/com.dashboard.nasdash/
```

这是飞牛的系统数据盘，**重启不丢**。各配置文件：

| 文件 | 内容 |
|------|------|
| `fan_mode.json` | 风扇手动/自动档位 |
| `fan_disk_temp.json` | 硬盘温控配置 |
| `fan_sys_temp.json` | 主板/CPU 温控配置 |
| `fan_labels.json` | 风扇自定义名称/隐藏 |
| `fan_curve_*.json` | 自定义曲线 |
| `fan_rules.json` | 逐风扇温度联动控速规则 |
| `alert_*.json` | 告警规则与通知渠道 |

> **重要修复（本版已修）**：早期版本有个隐蔽 bug——温控配置「存得进、读不出」，导致勾选在刷新/重启后丢失、温控实际不生效。现已修复，**保存后刷新/重启配置都还在**。如果你之前遇到「勾好的设置没了」，升级这版后就没事了。

## 五、常见问题排查

| 现象 | 是不是 bug | 怎么办 |
|------|-----------|--------|
| 风扇显示「无转速信号」 | 不是 | 该通道风扇没接测速线（3针/缺 tach）或空接口。仍能调速，点「隐藏」收起即可 |
| hwmon 编号跨重启变化 | 不是 | 内核给控制器分配的 `hwmonN` 会漂。面板已按通道序号(idx)命中真实通道，不影响调速，重启不乱 |
| 名字显示「it8772 风扇 N」 | 不是 | 旧 FanControlServer 配置残留标签。风扇卡片里改名即可 |
| 手动调速后停目标值不回弹 | 不是 | 设计行为：拖动即手动控制。点「恢复自动」才交还系统 |
| 滑块最低可到 0%（停转） | 不是 | 手动调速下限已放开到 0%，想完全停转选「停转」档位即可，不再卡在 10% |
| 勾好的温控设置重启没了 | **曾是 bug，已修** | 升级到含修复的版本即可；若仍丢，检查 `/vol1/@appdata/.../fan_disk_temp.json` 是否生成 |
| 启用硬盘温控但风扇不动 | 多半是没勾「受控风扇」 | 去「受控风扇」勾至少一个风扇再保存；面板会橙色提示 |
| 混了 SAS/SSD 盘，休眠停转不生效 | 已修复 | 升级后 SAS/SSD 标「常驻」自动排除，机械盘全睡即可停转 |
| 想让两台风扇跟同一温度却各用不同曲线 | 不是 bug | 用风扇卡片里的「温度联动控速」：两台都选「硬盘」源、各自填不同曲线即可，见 6.2.5 |
